## 零、总纲的自我定位（先立底线）

本 schema 只塑形，不改骨；只规范"名"的边界，不裁决"道"的真伪。

**核心信条（继承提示词）**：铸的是砖，不是庙。砖可砌墙，亦可作门槛；真正的道，在门槛之外。

**本版要解决的唯一问题**：如何在"为学日益"（原子化拆分）与"为道日损"（不替经典立新论）之间，给机器画一张**能承载"道"、又不越界"名"**的图纸。

---

## 一、三层核心构件

机备账 v1.1 将 schema 收敛为三层，各司其职、互不越界：

```
┌─────────────────────────────────────────────────┐
│ ① 节点层：本体-分相双层（同出而异名）              │
│ ② 边层：喻/实/逻辑/玄 四型 + 最小谓词集           │
│ ③ 状态层：ACTIVE/EXTENSION/XUAN/SILENT 四态       │
└─────────────────────────────────────────────────┘
        贯穿三层：静默机制（静默晶体 + 玄谓词 + SILENT态）；另有小澄真Validator守门
```

---

## 二、节点层：本体-分相双层（回应反馈2·同出边）

### 2.1 设计

强制统一实体名会丢失语境语义（"水"在不同章相位不同），故节点拆两层：

| 层 | 命名 | 用途 | 示例 |
|----|------|------|------|
| **本体节点** | 全局标准名 | 跨章召回、全局跳转 | `水` |
| **分相节点** | 本体名 + 章号 + 相位 | 保留单章语境、精准定位 | `水-8-上善`、`水-78-攻坚` |

两者用 `同出` 边连接（借《道德经》第1章"此两者同出而异名，同谓之玄"）：

```
(水-8-上善) ─[同出]─► (水) ◄─[同出]─ (水-78-攻坚)
```

### 2.2 强制规则

1. SPO 的 subject/object 一律使用**分相节点**（保语境）；跨章检索由本体节点召回。
2. `同出` 边的 status **必须标 `EXTENSION`**（见 §4.2）——因为"水有分相"是结构性类比借用，非文本直陈。
3. 禁止在 v1.1 阶段建立 `∈`（类属/上下位）边——那是替经典立新论的高危区（反馈1已否决）。

## 三、边层：四型边 + 最小谓词集（回应反馈1+2）

### 3.1 边类型（Edge Type，4 型）

| 边型 | 语义 | 谓词示例 | 推理策略 |
|------|------|---------|---------|
| **喻** | 比喻/类比 | 若、如、似 | 不传递因果，仅标记相位相似 |
| **实** | 直陈/定义/存在/生成/动作/状态 | 是、曰、生、成、处、居、有、无 | 正常遍历 |
| **逻辑** | 因果/条件/目的 | 故、则、因、以、若(条件义) | 正常遍历，承载因果链 |
| **玄** | 不可约、不可机械推断 | 玄 | **降权 + 提示人读 Agent** |

### 3.2 最小谓词集（Predicate，落在四型之下）

| 边型 | 谓词 |
|------|------|
| 喻 | 若、如、似 |
| 实 | 是、曰、是谓、有、无、生、成、化、静、动、宁、安 + 原文单字动词（居/处/与/言/正/事/心…） |
| 逻辑 | 故、则、因、以、若(条件) |
| 玄 | 玄（仅用于明确不可约的字：几、又、玄、妙） |

> **"若"字分判（谓词单字 + subtype 枚举必填）**：谓词恒为单字"若"，边型由 edge_type 承载，**分判由 subtype 枚举字段（必填）承载**：
> - `subtype: metaphor`（可替换"像/如同"）→ edge_type=喻
> - `subtype: condition`（可替换"如果/假如"）→ edge_type=逻辑
> - `subtype: reasoning`（可替换"乃/才"，王弼注"若，乃也"，如第13章"若可寄天下"）→ edge_type=逻辑
> - `subtype: interrogative`（可替换"何"，如第20章"相去若何"）→ 依语义定边型
>
> **Validator 硬校验**：凡 predicate="若" 且 subtype 缺失或非枚举值 → 拒收入库。机器读 subtype 零判断，原文不失真。两可时，从喻不从逻辑。详见《机备账·若字谓词分判规范·附录A》。

**禁止**：主张、构成、体现、包含、推动、导致、反映、关联、作用、指向、转化、超越、效法、原则、借鉴、教化、持守、实践——一切现代抽象动词。

### 3.3 玄谓词（回应反馈2·静默通道）

- 凡遇"几/又/玄/妙"等无法归入因果/条件/比喻的字词，**不强行归类**，标 `predicate="玄"`。
- 推理引擎遇 `predicate="玄"` 边：自动降低图遍历权重，改提示人读 Agent"此处需人文语境，不可机械推断"。
- **防膨胀红线①**：`玄` 只能用于**明确不可约**的字，禁止成为"懒得归类的兜底"。若一章出现 ≥3 条"玄"边，视为该章**尚未吃透**，退回人读账重读，不得强行入库。

### 3.4 再具体化规则（回应反馈1·reification）

属性在需要成为因果链主体时，允许提升为独立节点，但必须用固定谓词连接：

```
规则前（错误）：水 --不争--> ∅ ；不争 --故--> 无尤   （"不争"边/节点混用）
规则后（正确）：水 --有属性--> 不争 ；不争 --故--> 无尤  （属性实体化）
```

- 固定连接谓词：`有属性`（边型=实）。
- 属性实体化后的节点，须在 note 标注"reified"。

## 四、状态层：STATUS 四态（回应反馈2·静默评判）

### 4.1 定义

| STATUS | 含义 | 对应 |
|--------|------|------|
| **ACTIVE** | 文本直陈，可机器推理 | 🔵 文本事实 |
| **EXTENSION** | 创见延伸，非文本直陈 | 🟠 创见延伸 |
| **XUAN** | 冲突并存，两义皆可 | ⚪ 玄（不裁决） |
| **SILENT** | 静默，不提取（静默晶体） | ● |

### 4.2 强制规则

1. 每颗 SPO 入库前，必过 Validator 三问（§5.2），判定结果写入 STATUS。
2. `同出` 边一律 `EXTENSION`（§2.2）。
3. `玄` 边一律 `XUAN` 或 `SILENT`，**不得标 ACTIVE**。
4. `EXTENSION` 边在推理引擎中**降低权重**，且展示端必须显式标注"🟠创见"——不得与"🔵文本事实"混同。

## 五、静默机制（贯穿三层的"●"）

静默不是一层，是贯穿三层的三种形态：

| 形态 | 位置 | 语义 |
|------|------|------|
| **静默晶体** | 不入库的清单（仅存于空白日志，不属于任何 Schema 字段） | 决定不提取的"妙"，附 ≤10 字理由；仅记录，不入图谱，不参与推理 |
| **玄谓词** | 边层 | 入库但标"不可机械推断" |
| **STATUS=SILENT** | 状态层 | 入库但标"静默" |

> **表后注（留白提醒）**：以上三种形态，都只是"关于静默的标签"，不是静默本身。真正的静默是空白，不入本表、不入库、不属于本 schema 的任何字段——它只是一份永远不参与推理的空白清单。本表服务于"机器知道哪里该停"；那份空白，服务于"道本身永有出口"。

### 5.1 静默审查前置（反馈1）

在启动任何**跨章本体边**建设前，先执行静默观心：

> "这条边，是文本直陈，还是我的推演？"

若答案不明，**先不建**。跨章推理的冲动，恰是最需要"小澄真"驻场的地方。

### 5.2 小澄真 Validator（回应反馈2·守门员）

Validator 不判断"道"的真伪，只判断"名"的边界。每颗 SPO 入库前，问三个"●"之间的问题：

1. 这颗晶体，是文本直陈，还是我们的推演？
2. 如果是推演，是否在替经典立新论？
3. 如果立了新论，是否已标注为 `EXTENSION` 而非 `ACTIVE`？

**防膨胀红线②**：Validator 只做"文本-推演"二分提醒，**不裁决义理**。若 Validator 开始判断"哪个解释更对"，立即停机——它已越权，成为新的"决断者"。

## 六、schema 字段定义（v1.1）

### 6.1 单条 SPO 字段

```json
{
  "subject": "水-8-上善",        // 分相节点（必填）
  "subject_base": "水",          // 本体节点（必填）
  "predicate": "善利",           // 最小谓词集（必填）
  "edge_type": "实",             // 喻/实/逻辑/玄（必填）
  "object": "万物",              // 分相节点（必填，可为 null）
  "object_base": "万物",         // 本体节点（object 非 null 时必填）
  "source": "8.水善利万物",      // 章节+原文短句（必填）
  "status": "ACTIVE",            // 四态（必填）
  "subtype": null,               // 谓词语义细分（predicate=若 时必填）：metaphor/condition/reasoning/interrogative
  "x_wuxing": null,              // 可选：实体五行标注（来源 concept_wuxing_dict_v1.3，如 dominant=水）；仅供检索排序，不参与推理
  "note": null                   // 可选：版本差异/指代/reified/不可约说明
}
```

### 6.2 静默晶体字段

```json
{
  "●": "'几于道'中的'几'",
  "reason": "近而未及，防范畴错误"
}
```

## 八、防膨胀三条红线（本版新增，最高优先）

> 这三条红线不是规范，是规范的边界。任何一条被突破，立即停铸。

1. **玄谓词限死**：`玄` 只能用于明确不可约的字（几/又/玄/妙）；一章节 ≥3 条"玄"边，退回人读账重读。
2. **Validator 限权**：只做"文本-推演"二分提醒，不裁决义理；一旦开始判对错，立即停机。
3. **机制总量冻结**：本版 6 项机制（双层节点/四型边/最小集/玄谓词/reification/STATUS四态）**为上限**。下一版若新增，必须先删一旧——防止"为学日益"失控，重蹈"486 条关联"覆辙。
   **例外（静默不受冻结）**：本冻结令**不适用于静默形态**。静默是边界不是机制，新发现的"不可说"可随时新增安放形态，不受"新增先删旧"约束。

## 九、与双账本架构的关系

机备账 v1.1 是"机备账"（机器口粮）的 schema，与"人读账"（五步读解）**并列、分开、互相滋养**：

```
人读账（五步读解）──回收站──► 机备账（本 schema）──回灌──► 人读账
        （为人说）              （为机器备）              （反哺读解）
                        └──净化──► ●静默晶体
```

本 schema 只规范"机备账"一侧。回收站/回灌/净化三接口的完整设计，另出《道境知识图谱双账本架构》总纲。

## 十、一句话总纲

> **机备账 v1.1 把"名可名，非常名"落成了机器的图纸：本体-分相双层节点接住"同出而异名"（跨章召回不失语境），喻/实/逻辑/玄四型边让机器"该推则推、该止则止"，STATUS 四态让"文本事实"与"创见延伸"永不混同——而贯穿三层的那枚"●"，从提示词的软纪律，锻成了 schema 的硬约束。三条防膨胀红线，是这张图纸的边界：机制总量冻结，一旦突破，停铸。至于"道"本身——窗在纸外，此页留白。**

*继承提示词心法：铸的是砖，不是庙。名可名，非常名。*
