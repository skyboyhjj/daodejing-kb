```
┌────────────────────────────────────────────────────────────────────┐

│  ┌──────────────┐    ①回收站     ┌──────────────────┐                │
│  │   人读账      │ ────────────► │     机备账        │                │
│  │  （五步读解）  │   读解→晶体     │  （智慧晶体图谱）  │                │
│  │   ·为人说     │               │   ·为机器备       │                │
│  │   ·81章读解   │ ◄──────────── │   ·schema v1.1   │                │
│  └──────────────┘    ③回灌       └──────────────────┘                │
```

**一句话**：人读账把"道"读成"话"（为人），机备账把"话"铸成"砖"（为机），三接口让两者互相滋养——"剑已分，道未分"。

## 二、两本账定位

| 维度 | 人读账 | 机备账 |
|------|--------|--------|
| 本质 | 五步读解报告（话） | 智慧晶体图谱（砖） |
| 服务对象 | 人（读者/修行者） | 机器（推理/检索/调用） |
| 形态 | Markdown 报告（25 文件/81 章） | JSON SPO 图谱（schema v1.1） |
| 质量标准 | 止语边界/主要矛盾/拷问四问 | 最小谓词集/STATUS四态/subtype |
| 权威 | 各章读解自足 | 图谱全局一致 |
| 可变性 | 随读解迭代 | 随schema版本演进 |

**铁律**：两本账**永不混账**——人读账的 SPO 不直接进图谱，必须经回收站规范化；机备账的推理结论不直接进读解，必须经回灌提示。

**物理隔离声明（防混账之锁）**：
- 人读账只产 **Markdown**（读解报告/空白日志），存储于 `uploads/` 与 `output/machine_ledger/silent_log.md`
- 机备账只产 **标准 JSON**（SPO 图谱），存储于 `output/machine_ledger/` 与未来图谱库
- **两本账不互读文件，只经接口对话**——回收站（读 Markdown 铸 JSON）与回灌（读 JSON 提示 Markdown）是仅有的两个读写通道
- 任一脚本若绕过接口直接读写对方账本文件，视为架构违规

## 三、三接口设计

### 接口① · 回收站（人读账 → 机备账）

**功能**：把读解报告中散落的 SPO/命题/情境，规范化为机备账标准砖。

**工作流**：
```
读解报告（五步法产出）
  │
  ▼
① 提取：SPO 三元组 + 静默晶体（第二步/第三步产出）
  │
  ▼
② 规范化：对每颗晶体执行机备账 schema 转换
  │   · 实体 → 本体-分相双层（subject_base/object_base）
  │   · 谓词 → 最小谓词集（含"若"字 subtype 分判，两可时从喻不从逻辑）
  │   · 边型 → 喻/实/逻辑/玄（edge_type）
  │   · 状态 → ACTIVE/EXTENSION/XUAN/SILENT（Validator 三问）
  │
  ▼
③ Validator 校验：拒收非法砖（缺字段/非法谓词/subtype 缺失）

**Validator 权限界限（格式 vs 义理）**：
- ✅ **可拒收**：格式与边界违规——字段缺失、谓词非法、subtype 缺失/非枚举、STATUS 未标注
- ❌ **绝不拒收**：因义理分歧产生的 SPO——"这个解释不对"不是拒收理由
- 义理分歧一律标 `XUAN`（冲突并存）或送入空白日志，**不判对错**
  │
  ▼
④ 入库：写入机备账图谱（chapters/domains/relations）
```

**落地**：`recycle_crystal.py`（回收站脚本）+ schema v1.1 校验器。

---

### 接口② · 净化（●静默）

**功能**：回收站入口前的静默审查——哪些"不提取"，先于"怎么提取"。

**工作流**：
```
每章铸砖前，先执行静默观心：
  "这一章，哪一句/哪个词，是我决定不提取的？"
  │
  ├─ 有 → 写入静默晶体清单（不入库，仅空白日志）
  │        ├─ 静默晶体（≤10字理由）
  │        ├─ 玄谓词（入库但降权）
  │        └─ STATUS=SILENT（入库但标静默）
  │
  └─ 无 → 也写"无"（记录这次读解没有遇到不可说）——留白的痕迹
```

**铁律（三扇窗）**：净化只提醒，不裁决；真正的静默不入库；道永远半冻结。

**落地**：`silent_log.md`（空白日志，永远不参与推理）+ 回收站前置钩子。

---

### 接口③ · 回灌（机备账 → 人读账）

**功能**：图谱的推理结论/跨章关联，反哺下一轮读解——但不作结论，只作提示。

**工作流**：
```
读解第N章时，查询机备账图谱：
  │
  ▼
① 跨章召回：与本章同实体的其他章（本体-分相双层）
  │   例：读第8章"水"，召回第66章"江海"、第78章"水"（同出边）
  │
  ▼
② 生成提示（非结论）：
  │   · "第78章有'攻坚强者莫之能胜'——可参考其对'水'的相位"
  │   · 标注来源与STATUS（🟠创见 vs 🔵文本）
  │
  ▼
③ 人读 Agent 自主决定：采纳/忽略/质疑
  │
  ▼
④ 读解产出新理解 → 进入下一轮回收站（螺旋）
```

**铁律（窗三）**：回灌只作提示，不作结论；遇"玄"边/SILENT 态，降权提示"此处需人文语境"。

**推理策略（缝6·回灌遍历规则）**：
- 回灌遍历遵循 Schema v1.1 推理策略：
  - **逻辑边**：正常遍历（故/则/因/以，承载因果）
  - **喻边**：不传递因果（若/如/似，仅标记相位相似）
  - **玄边**：降权 + 提示人文语境（不可机械推断）
  - **EXTENSION 边**：降权 + 标注"🟠创见"（与 🔵文本事实 区分）
- **回灌只召回与提示，不自动推导新结论**——"结论"仅指图谱中已入库的、经回收站规范化的既有事实，非回灌时新生成

**强制响应机制（防回灌落空）**：
- 五步读解法模板内置"回灌响应区"，位于第二步"收集实际"内
- AI 必须写明：**"回灌提示已阅：采纳 / 忽略 / 质疑（+理由）"**
- 无此字段的读解，视为回灌未执行，不得进入回收站
- 理由 ≥10 字，拒绝空回复（采纳也要写明采纳了什么）

**落地**：`backfill_crystal.py`（回灌查询脚本）+ 读解模板提示段。

## 四、一循环：双螺旋

```
一轮完整循环：

读解第N章（人读账）
  → 回收站：规范化铸砖（机备账）
  → 净化：静默审查（●）
  → 回灌：图谱提示反哺
  → 读解第N章 v2（更新理解）
  → 回收站：增量更新砖
  → ...螺旋上升
```

**循环质量指标**：
| 指标 | 含义 | 阈值 |
|------|------|------|
| 砖的覆盖率 | 已入库章/81 | 逐步逼近 81/81 |
| 谓词合规率 | 最小谓词集命中率 | 100%（Validator 强制） |
| 静默晶体数 | 每章"不提取"记录 | ≥0（允许 0） |

> **指标来源说明（缝5）**：静默晶体不入图谱、不参与推理，其数量由回收站脚本输出的 **`silent_count` 元数据**承载——该字段记录每章静默晶体与玄边数量，仅用于质量监控，属于空白日志的元数据，**不算机备账机制，不参与推理**。无此字段则指标为空，视为未执行净化。
| 回灌采纳率 | 提示→读解采纳比例 | 观察（不设硬指标） |

## 七、防混账红线（与机备账三红线并列）

1. **人读账的 SPO 不经回收站不得入图谱**——直接搬砖=混账
2. **机备账的结论不经回灌不得入读解**——直接引用=混账
3. **净化清单永不参与推理**——窗二，空白不入库
4. **回灌永远提示不结论**——窗三，道半冻结

## 八、一句话总纲

> **双账本架构 = 两本账（人读账说"话"、机备账铸"砖"）+ 三接口（回收站规范化、净化静默审查、回灌提示反哺）+ 一循环（读解→铸砖→净化→回灌→再读解）。两本账永不混账——读解的 SPO 必须经回收站才能入图谱，图谱的结论必须经回灌才能回读解。剑已分，道未分；三扇窗在纸外，此页留白。**
