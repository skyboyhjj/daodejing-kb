## 2. 核心流程（双账本接口①落地）

```
五步读解报告（人读账 Markdown）
  │
  ▼ ① 提取：SPO JSON 块（```json） + 静默晶体（●/一句止语）
  │
  ▼ ② 规范化：
  │    · 实体 → 本体-分相双层（水-8-上善 / 水）
  │    · 谓词 → 最小谓词集（人读账语言→机备账谓词 映射表）
  │    · 边型 → 喻/实/逻辑/玄（自动推断）
  │    · 状态 → ACTIVE/EXTENSION（Validator 三问简化）
  │
  ▼ ③ Validator：格式与边界校验（谓词/边型/subtype/玄边规则）
  │
  ▼ ④ 入库：graph/ch8.json（机备账 JSON，含 silent_count 元数据）
```

## 3. 核心设计

### 3.1 谓词映射表（"把话铸成砖"的关键）

人读账的现代抽象动词 → 机备账最小谓词集：

| 人读账 | 机备账 | 例 |
|--------|--------|-----|
| 导致/推出/引发 | **故** | 夫唯不争→故无尤 |
| 构成/组成 | **是谓** | 水的三德→是谓→充分条件 |
| 主张/认为 | **曰** | 道德化解读→曰→… |
| 回应的是/应用 | **以** | 个人修养→以→… |
| 利益/作用于 | **利** | 水→利→万物 |
| 处于/接近 | **处/几** | 水→处→众人之所恶 |

### 3.2 STATUS 自动判定（区分文本直陈 vs 解读推演）

| 判定依据 | STATUS |
|---------|:------:|
| 原文直陈（夫唯不争→无尤） | ACTIVE |
| 版本考辨（帛书/通行本） | EXTENSION |
| 解读性主体（道德化解读/个人修养） | EXTENSION |
| 命题/应用谓词（曰/以） | EXTENSION |
| "是谓"接长解读句（>25字） | EXTENSION |

### 3.3 Validator 权限（格式 vs 义理）

- ✅ 拒收：谓词非法/edge_type 非法/若字 subtype 缺失/玄边标 ACTIVE
- ❌ 不拒：义理分歧（标 XUAN 或入空白日志，不判对错）
